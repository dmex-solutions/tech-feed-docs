## Enhancements

### 1. Generated Serial Numbers Saved as Active (DMEX_PRO_7266)
**Location:** You can access Serial No Generate, Control Task and Final Inspection under **Production & Quality → Operations**  

**Services:** operationsvcs, infographicssvcs, poweb, query-log

**Details:**
- **Serial No Bulk Generate** saves each serial's first-process `controltask` row as `processStatus = NEW`, `partStatus = NEW`, `active = 1` (earlier `active = 0`). Every NEW serial now follows one rule: only active rows are used.
- **operationsvcs – `control-task.service.ts`:**
  - `generateSerialNumbersInBulk` and `create` (when `processStatus = NEW`) set `active = 1`.
  - `handleFipAndDeleteControlTasks`: a deleted first-process task is reset to NEW with `active = 1`, so the serial can be used again.
  - Override plan reset at the starting override process uses `active = 1`.
  - First-process serial lists (Supplier Job Work Out, Service DC Out, OS Inward Inspection summary) read NEW serials as `processStatus = 'NEW' AND active = 1`.
  - Final Inspection header status: `FNEW` while any linked row is NEW and active, otherwise `FCLS`.
- **poweb – Supplier Job Work Out:** the first-process serial picker requests `isActive=1`.
- **infographicssvcs – Batch Usage:** rows with `partStatus = NEW` map to a new serial state `GENERATED`, shown as **Not started** (not counted as WIP OP30 or Not located).
- **Data backfill (query-log `qandq.sql`, v26.19):** sets `active = 1` on `controltask` rows with `processStatus = NEW`, `partStatus = NEW`, `active = 0`, skipping serials that already have an active row in the same control plan. Run per tenant; run it as a `SELECT` first to check the row count.
