## Enhancements

### 1. Generated Serial Numbers Saved as Active (DMEX_PRO_7266)
**Location:** You can access Serial No Generate, Control Task and Final Inspection under **Production & Quality → Operations**  

**Services:** operationsvcs, infographicssvcs, poweb, query-log

**Details:**
- **Serial No Bulk Generate** saves each serial's first-process `controltask` row as `processStatus = NEW`, `partStatus = NEW`, `active = 1` (earlier `active = 0`). Every NEW serial now follows one rule: only active rows are used.
- **operationsvcs – `control-task.service.ts`:**
  - `generateSerialNumbersInBulk` and `create` (when `processStatus = NEW`) set `active = 1`.
  - `handleFipAndDeleteControlTasks`: a deleted first-process task is reset to NEW with `active = 1`, so the serial can be used again.
  - Override plan reset at the starting override process uses `active = 1`.
  - First-process serial lists (Supplier Job Work Out, Service DC Out, OS Inward Inspection summary) read NEW serials as `processStatus = 'NEW' AND active = 1`.
  - Final Inspection header status: `FNEW` while any linked row is NEW and active, otherwise `FCLS`.
- **poweb – Supplier Job Work Out:** the first-process serial picker requests `isActive=1`.
- **infographicssvcs – Batch Usage:** rows with `partStatus = NEW` map to a new serial state `GENERATED`, shown as **Not started** (not counted as WIP OP30 or Not located).
- **Data backfill (query-log `qandq.sql`, v26.19):** sets `active = 1` on `controltask` rows with `processStatus = NEW`, `partStatus = NEW`, `active = 0`, skipping serials that already have an active row in the same control plan. Run per tenant; run it as a `SELECT` first to check the row count.

### 2. Stock Ledger Validation – Not Processed Returns in Batch / Work Order (DMEX_PRO_7270)
**Location:** You can access Stock Ledger Validation under **Production & Quality → Reports**  

**Services:** infographicssvcs, poweb

**Details:**
- When a first-process serial sent on Supplier Job Work is marked **Not Processed** in OS Inward Inspection, operationsvcs (`saveOutsourceNotProcessedStockLedger`) posts the quantity back IN to Batch / Work Order (stage `WO`, OP25) in the Stock Ledger. The Stock Ledger behaviour is unchanged; Stock Validation is aligned to it.
- **infographicssvcs – `stock-batch-usage.logic.ts`:**
  - `batchSerialCountQuery` returns `notProcessedQty`: first-process serials of the batch in `osinwardinspectionxnotprocessedserialno`, only for OS Inward Inspections not deleted and with status other than `DRAFT` / `REJECTED` (when the ledger return is posted).
  - `classifyBatches`: Batch / Work Order [IN SCREEN] qty = batch qty − started serials + Not Processed returns, never above the batch qty. `notProcessedQty` is returned on each batch line.
- **poweb – Stock Ledger Validation:** the batch line in the Batch / Work Order popup shows the return, e.g. "100 serial no generated, 10 started, 1 returned Not Processed".
- Example: batch with 100 qty, 10 serials started, 1 returned Not Processed → ledger and [IN SCREEN] both show 91.

### 3. Hold Release – Stock Moves Out of the Hold Bucket (DMEX_PRO_7299)
**Location:** You can access Control Task (Pending Validation) under **Production & Quality → Operations** and Stock Ledger Validation under **Production & Quality → Reports**  

**Services:** operationsvcs

**Details:**
- **operationsvcs – `control-task.service.ts` `update()`:** the OUT bucket (`existingPartStatus`) of a release is now resolved by the new `resolveExistingStockBucket`, from the row being released (`existingTask`) or the serial's active `controltask` row at the same `controlProcessId`. Earlier it read any active row of the serial no, across parts.
- A serial no that is also active on another part no longer decides the bucket, so a Hold (HI / HR) → Approved release posts `OUT HOLD` / `IN APV` at the held process, and Stock Ledger Validation Hold / Approved match [IN SCREEN].
- Data already posted as `OUT APV` / `IN APV` on a release needs a Stock Adjustment (`OUT HOLD` / `IN APV`) per serial.
